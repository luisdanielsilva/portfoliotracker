# systemd units

Copies of the units this deployment actually runs, kept here because they used to live only in
`/etc/systemd/system/` — which is root-owned, outside the repo, and invisible to every code
review. When the project directory moved, `WorkingDirectory`, `DB_PATH` and `ExecStart` went on
pointing at the old path and the price fetch died for about fourteen hours without a sound. The
code that broke was in git; the file that broke was not.

**These files are copies, not the live units.** systemd reads `/etc/systemd/system/`. Editing
anything here changes nothing until it is installed, and editing the live unit without copying it
back leaves this directory lying.

## What each one is

| File | What it does |
|---|---|
| `portfolio-price-fetch.timer` | Fires the fetch daily at **09:00 local time**. `Persistent=true` catches up a run missed while the machine was off. |
| `portfolio-price-fetch.service` | The job itself — `node price-fetch.js`: quote every held ticker, store, evaluate alerts, mail the digest and the run report. `Type=oneshot`, driven by the timer. |
| `pm2-deploy.service` | Generated by `pm2 startup`, not written by hand. Resurrects the pm2 process list at boot, which is what brings `portfolio-api` back. Regenerate rather than hand-edit: `pm2 startup systemd -u deploy --hp /home/deploy`, then `pm2 save`. |

There is no unit for the backups or the health check — those are cron, and `crontab -l` is the
only copy. See *Scheduled Tasks* in `README.md`.

## Installing after a change

```sh
sudo cp deploy/systemd/portfolio-price-fetch.{timer,service} /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now portfolio-price-fetch.timer
systemctl list-timers portfolio-price-fetch.timer   # empty output means NOT armed
```

`daemon-reload` on its own does not re-trigger anything. `enable --now` starts the timer, not the
job — but note that a timer carrying an `OnBootSec=` whose window has already passed fires the job
*immediately* on start. That is why this timer has none; `Persistent=true` covers the same case
without the surprise extra run.

## Checking these copies still match reality

Drift is the whole failure mode, so check it rather than trust it:

```sh
for f in portfolio-price-fetch.timer portfolio-price-fetch.service pm2-deploy.service; do
  diff -u "/etc/systemd/system/$f" "deploy/systemd/$f" && echo "$f: in sync"
done
```

Worth running after any change to the deployment path, the Node version, or the schedule.
